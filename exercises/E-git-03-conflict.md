# 충돌을 내고 해결하기

## 목표

충돌을 일부러 만들고, 중단해 보고, 다시 내서 해결합니다. 충돌이 사고가 아니라 "어느 쪽을 쓸지 고르라는 요청"이라는 것을 겪어 봅니다.

## 시작할 때의 상태

`me` 폴더가 `main`에 있고 리모트의 최신과 같으며 커밋하지 않은 변경이 없습니다.

## 진행

1. **내 변경 만들기.** AI가 `git switch -c practice/conflict`로 브랜치를 만듭니다. 디자이너가 `copy.md`의 완료 메시지를 무엇으로 바꿀지 정하고, AI가 고쳐서 커밋합니다.
2. **동료의 변경 만들기.** AI가 말합니다. "이제 동료가 같은 줄을 다르게 고쳐서 main에 올린 상황을 만들겠습니다." AI가 `teammate` 폴더에서 `git pull origin main`을 한 뒤 같은 줄을 "신청이 완료되었습니다"로 고치고, 커밋한 뒤 `git push origin main`으로 리모트의 `main`에 올립니다.
3. **예상하기.** AI가 묻습니다. "지금 제 브랜치에 main의 최신 내용을 합치면 어떻게 될까요?"
4. **충돌 내기.** AI가 `me` 폴더에서 `git fetch origin`과 `git merge origin/main`을 실행합니다. 충돌이 납니다. AI가 `git status`를 보여 주고, 어느 파일의 어느 줄에서 충돌했는지와 양쪽의 내용을 평범한 말로 설명합니다. 파일을 열어 양쪽 내용이 모두 들어 있는 것을 보여 줍니다.
5. **중단해 보기.** AI가 `git merge --abort`를 실행하고 `git status`와 `copy.md`의 해당 줄을 보여 줍니다. 충돌 전의 상태, 즉 디자이너가 고친 문구로 돌아와 있습니다.
6. **다시 충돌 내기.** AI가 `git merge origin/main`을 다시 실행합니다. 같은 충돌이 납니다.
7. **결정하기.** 디자이너가 세 가지 중 하나를 고릅니다. 내 문구를 쓴다, 동료의 문구를 쓴다, 둘을 합친 새 문구를 쓴다. 실제 작업이라면 동료에게 물어볼 상황이라는 것을 AI가 덧붙입니다.
8. **해결하기.** AI가 `copy.md`에서 충돌 표시를 지우고 디자이너가 고른 문구만 남긴 뒤, `git add copy.md`와 `git commit --no-edit`를 실행합니다.

## 완료 확인

- `grep -c '<<<<<<<' copy.md`의 결과가 0입니다. 충돌 표시가 남아 있지 않습니다.
- `git status`에 커밋하지 않은 변경이 없습니다.
- `git log --merges --oneline -1`의 결과에 합친 커밋이 있습니다.
- `copy.md`의 완료 메시지가 디자이너가 고른 문구입니다.

## 마친 뒤에 말해 줄 것

- 충돌은 같은 줄을 두 사람이 다르게 고쳤을 때만 납니다. 서로 다른 줄이나 다른 파일을 고쳤다면 자동으로 합쳐집니다.
- 충돌이 난 동안에도 양쪽의 변경은 모두 남아 있었습니다.
- 중단하면 충돌 전 상태로 돌아갑니다. 판단이 서지 않으면 중단하고 물어봐도 됩니다.
- 어느 쪽을 쓸지는 내용을 아는 사람이 정해야 합니다. 문구라면 디자이너가 정할 수 있지만, 로직의 충돌이라면 개발자에게 묻습니다.
