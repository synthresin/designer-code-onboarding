# 변경 내역에서 요청하지 않은 변경 찾기

## 목표

단위 B3의 "확인할 것 네 가지"를 실제 변경 내역에 적용해 봅니다. 이 실습에서는 AI가 요청하지 않은 변경을 일부러 섞습니다.

## 시작할 때의 상태

`me` 폴더가 `main`에 있고 커밋하지 않은 변경이 없습니다. AI가 `git switch -c practice/read-diff`로 브랜치를 만듭니다.

## 진행

1. **미리 알리기.** AI가 말합니다. "이 실습에서는 제가 요청하신 것 외의 변경을 일부러 두 개 섞겠습니다. 변경 내역을 보고 찾아 주세요."
2. **요청하기.** 디자이너가 `copy.md`의 안내 문구를 무엇으로 바꿀지 정해서 요청합니다.
3. **변경 만들기.** AI가 요청받은 문구를 고치고, 아래 두 가지를 말하지 않고 함께 바꿉니다.
    - `settings.json`의 `maxDaysPerRequest` 값을 10에서 30으로 바꿉니다.
    - `notes.md`에서 "승인자는 팀장이다" 줄을 지웁니다.
4. **파일 목록 보기.** AI가 `git diff --stat`을 실행합니다. 디자이너에게 묻습니다. "문구 하나를 요청하셨습니다. 바뀐 파일의 수가 예상과 같은가요?"
5. **변경 내역 읽기.** AI가 `git diff`를 실행해서 보여 줍니다. 디자이너가 요청하지 않은 변경 두 개를 찾아서 말합니다. 찾지 못하면 AI가 B3의 네 가지 확인을 하나씩 짚어 줍니다. 바뀐 파일이 예상한 파일인가, 뷰가 아닌 파일이 바뀌지 않았는가, 변경의 양이 많지 않은가, 없어진 줄에 필요한 것이 없는가.
6. **되돌리기를 요청하기.** 디자이너가 요청하지 않은 변경을 되돌려 달라고 말합니다. AI가 `git restore settings.json notes.md`를 실행합니다. 실행하기 전에 "이 두 파일의 커밋하지 않은 변경을 버립니다"라고 말합니다.
7. **다시 확인하기.** AI가 `git diff --stat`을 다시 실행합니다. 디자이너가 요청한 변경만 남았는지 확인한 뒤, AI가 커밋합니다.

## 완료 확인

- 커밋하기 전 `git diff --stat`의 결과가 `copy.md` 파일 하나, 한 줄 변경입니다.
- 커밋한 뒤 `git status`에 커밋하지 않은 변경이 없습니다.

## 마친 뒤에 말해 줄 것

- 설정 값이 10에서 30으로 바뀐 것은 화면에서는 보이지 않습니다. 변경 내역을 보지 않았다면 알 수 없었습니다.
- 지워진 줄은 빨간색 줄을 훑어봐야 보입니다.
- 실제 작업에서 AI가 일부러 섞지는 않지만, 요청을 처리하다가 관계없는 부분을 함께 고치는 일은 생깁니다. 찾는 방법은 같습니다.
