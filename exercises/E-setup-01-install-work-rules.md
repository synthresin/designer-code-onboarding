# 디자이너용 작업 규칙을 내 AI 코딩 앱에 설치하기

## 목표

지금까지의 실습은 연습 폴더에서 했습니다. 이제부터는 실제 레포의 파일을 고치게 되므로, 그 전에 디자이너용 작업 규칙(`skills/designer-work-rules/SKILL.md`)을 내 컴퓨터에 설치합니다. 이 온보딩 폴더 안에만 있으면 다른 레포를 열었을 때 AI가 이 규칙을 알지 못합니다.

설치는 두 가지를 넣는 일입니다.

- 개인 스킬 폴더에 스킬 파일을 넣습니다. 개인 스킬 폴더의 스킬은 어느 레포를 열든 쓸 수 있습니다.
- 개인 지침 파일에 "사용자는 디자이너이고, 파일을 수정하기 전에 이 스킬을 따른다"는 문단을 넣습니다. 개인 지침 파일은 AI가 모든 대화를 시작할 때 읽는 파일입니다. 스킬만 넣으면 AI가 요청의 내용을 보고 스킬을 쓸지 스스로 판단하는데, 사용자가 디자이너라고 말하지 않으면 쓰지 않을 수 있습니다. 이 문단이 있으면 말하지 않아도 적용됩니다.

## 시작하기 전에 확인할 것

- `company/CONTEXT.md`에 작업 규칙을 다른 방법(예: 회사의 스킬 배포 창구)으로 설치하라고 적혀 있으면, 4번의 스킬 파일 복사 대신 그 방법을 따릅니다. 5번의 개인 지침 파일은 그대로 진행합니다.
- `company/` 폴더가 없는 일반 과정에서는 설치를 기본으로 하지 않습니다. 1번과 2번의 설명까지만 하고, 디자이너가 원할 때만 3번 이후를 진행합니다.

## 진행

1. **규칙 소개하기.** AI가 `skills/designer-work-rules/SKILL.md`를 읽고, 이 규칙이 하는 일을 다섯 가지로 설명합니다. 뷰만 고친다, 로직을 바꿔야 하면 멈춘다, 디자인 시스템을 먼저 쓴다, 재사용 의도를 확인한다, 명령을 실행하기 전에 설명한다.
2. **레포 쪽에도 있어야 하는 것을 설명하기.** 수정해도 되는 폴더의 목록은 각 레포의 지침 파일에 있는 "디자이너 작업 범위" 항목에 있습니다. 항목이 없는 회사 레포에서는 AI가 파일을 수정하지 않고, 그 레포의 개발자에게 항목 추가를 요청하라고 안내합니다. 개인 프로젝트에서는 AI가 개인 프로젝트인지 물어본 뒤 범위 제한 없이 진행합니다. 설명이나 위치 찾기 같은 읽기 요청은 항목이 없어도 됩니다.
3. **예상하기.** AI가 묻습니다. "이 규칙을 설치한 뒤에, 디자이너 작업 범위 항목이 없는 회사 레포에서 문구를 고쳐 달라고 하면 어떻게 될까요?"
4. **스킬 파일 넣기.** AI가 지금 실행 중인 앱에 맞는 개인 스킬 폴더로 스킬 파일을 복사합니다. 실행하기 전에 어느 폴더에 무엇을 복사하는지 말합니다. 어느 앱인지 분명하지 않거나 디자이너가 두 앱을 모두 쓰면 양쪽에 복사합니다. 같은 위치에 이미 파일이 있으면 덮어쓰기 전에 말합니다.

    | 앱 | 스킬 파일의 위치 |
    | --- | --- |
    | Claude Code | `~/.claude/skills/designer-work-rules/SKILL.md` |
    | Codex | `~/.agents/skills/designer-work-rules/SKILL.md` |

    ```
    mkdir -p ~/.claude/skills/designer-work-rules
    cp skills/designer-work-rules/SKILL.md ~/.claude/skills/designer-work-rules/SKILL.md
    ```

5. **개인 지침 파일에 문단 넣기.** AI가 앱에 맞는 개인 지침 파일의 끝에 아래 문단을 추가합니다. 파일이 없으면 만들고, 파일에 이미 있던 내용은 건드리지 않습니다. 같은 표시 줄로 둘러싸인 문단이 이미 있으면 그 문단만 새 내용으로 바꿉니다. 스킬 파일의 위치는 4번에서 실제로 넣은 위치로 적습니다.

    | 앱 | 개인 지침 파일 |
    | --- | --- |
    | Claude Code | `~/.claude/CLAUDE.md` |
    | Codex | `~/.codex/AGENTS.md` |

    ```
    <!-- designer-work-rules 시작 -->
    ## 디자이너 작업 규칙

    이 컴퓨터의 사용자는 디자이너입니다. 레포의 파일을 수정하거나 새로 만드는 요청을 받으면, 사용자가 디자이너라고 말하지 않아도 수정하기 전에 designer-work-rules 스킬(~/.claude/skills/designer-work-rules/SKILL.md)을 읽고 그 규칙을 따릅니다. 디자이너 코드 협업 온보딩 자료 폴더와 연습 폴더(~/onboarding-practice)에서는 적용하지 않습니다.
    <!-- designer-work-rules 끝 -->
    ```

6. **확인하기.** AI가 스킬 파일이 넣은 위치에 있고 온보딩 폴더의 파일과 내용이 같은지, 개인 지침 파일에 표시 줄로 둘러싸인 문단이 한 번만 있는지 확인합니다.
7. **적용되는 시점 알리기.** AI가 말합니다. "새 대화부터 적용됩니다. 다음에 다른 레포를 열어 수정을 요청할 때, 디자이너라고 말하지 않아도 제가 디자이너 작업 범위를 먼저 확인하는지 봐 주세요."

## 완료 확인

- 스킬 파일을 `diff`로 비교했을 때 온보딩 폴더의 파일과 차이가 없습니다.
- 개인 지침 파일에서 `designer-work-rules 시작`이라는 줄을 검색하면 한 번 나옵니다.

## 마친 뒤에 말해 줄 것

- 이 규칙은 온보딩이 끝난 뒤에도 계속 적용됩니다.
- 온보딩 저장소의 규칙이 바뀌면 이 폴더에서 최신 내용을 받은 뒤 "작업 규칙을 다시 설치해줘"라고 말하면 됩니다.
- 지우고 싶으면 "작업 규칙을 지워줘"라고 말합니다. 스킬 폴더와, 개인 지침 파일에서 표시 줄로 둘러싸인 문단을 지웁니다.
