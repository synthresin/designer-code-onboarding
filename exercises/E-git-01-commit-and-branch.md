# 커밋하고 브랜치를 만들어 보기

## 목표

단위 B1에서 읽은 네 가지(커밋, 브랜치, 로컬과 리모트, 푸시)를 연습 폴더에서 한 번씩 직접 겪어 봅니다.

## 시작할 때의 상태

`exercises/README.md`의 공통 준비가 되어 있고, `me` 폴더가 `main`에 있으며 커밋하지 않은 변경이 없습니다.

## 진행

1. **현재 상태 보기.** AI가 `git status`와 `git log --oneline`을 실행하고, 지금 어느 브랜치에 있는지와 커밋이 몇 개 있는지를 말로 설명합니다.
2. **파일 고치기.** 디자이너가 `copy.md`의 버튼 문구를 무엇으로 바꿀지 정합니다. AI가 그 줄을 고쳐서 저장합니다.
3. **예상하기.** AI가 묻습니다. "파일은 저장됐습니다. 지금 이 변경은 git에 기록되어 있을까요? 리모트에는 있을까요?" 디자이너가 답한 뒤, AI가 `git status`를 실행해서 "고쳐졌지만 커밋되지 않은 파일"로 표시되는 것을 보여 줍니다.
4. **브랜치 만들고 커밋하기.** AI가 `git switch -c practice/change-copy`로 브랜치를 만들고, `git commit -am "(디자이너가 정한 메시지)"`로 커밋합니다. 실행하기 전에 각 명령이 무엇을 하는지 한 문장으로 말합니다.
5. **브랜치를 바꾸면 파일이 바뀌는 것을 보기.** AI가 `git switch main`을 실행하고 `copy.md`의 버튼 줄을 보여 줍니다. 고치기 전의 문구가 보입니다. 다시 `git switch practice/change-copy`를 실행하고 같은 줄을 보여 줍니다. 고친 문구가 보입니다. 디자이너에게 왜 그런지 설명해 보게 합니다.
6. **예상하기.** AI가 묻습니다. "지금 리모트에는 이 브랜치가 있을까요?" 디자이너가 답한 뒤, AI가 `git -C ../remote.git branch`를 실행해서 `main`만 있는 것을 보여 줍니다.
7. **푸시하기.** AI가 `git push -u origin practice/change-copy`를 실행하고, 다시 리모트의 브랜치 목록을 보여 줍니다. 이번에는 브랜치가 있습니다.

## 완료 확인

- `git log --oneline main..practice/change-copy`의 결과가 커밋 1개입니다.
- `git -C ../remote.git branch`의 결과에 `practice/change-copy`가 있습니다.

## 마친 뒤에 말해 줄 것

- 저장, 커밋, 푸시는 각각 다른 일입니다. 저장은 파일만 바꾸고, 커밋은 내 컴퓨터의 기록에 남기고, 푸시는 그 기록을 리모트로 보냅니다.
- 브랜치를 바꾸면 폴더의 파일이 그 브랜치의 내용으로 바뀝니다. 파일이 없어진 것이 아니라 다른 브랜치에 있는 것입니다.
- 이 실습에서 `main`은 바뀌지 않았습니다. 실제 작업에서는 여기서 PR을 올려 `main`에 합쳐 달라고 요청합니다.
