# 재사용 단위를 AI에게 지시하고 점검하기

어떤 덩어리를 여러 화면에서 함께 쓰려는지는 디자이너만 알고 있습니다. 말하지 않으면 AI는 지금 화면에 필요한 것을 그 자리에 새로 만들고, 같은 모양의 코드가 화면마다 따로 생깁니다. 그래서 재사용 의도는 작업을 시작할 때 디자이너가 먼저 말하고, PR을 올리기 전에 디자이너가 점검합니다.

## 1. 작업을 시작할 때: 덩어리를 네 종류로 분류해서 말합니다

시안의 덩어리를 아래 네 종류로 나눕니다.

| 종류 | 뜻 | AI가 할 일 |
| --- | --- | --- |
| 디자인 시스템 컴포넌트 | 디자인 시스템 패키지에 있는 것입니다 | 가져다 쓰고 props만 정합니다 |
| 이미 있는 공용 컴포넌트 | 이 프로젝트 안에 누군가 만들어 둔 것입니다 | 찾아서 가져다 씁니다. 새로 만들지 않습니다 |
| 새 공용 컴포넌트 | 아직 없지만 여러 화면에서 쓸 것입니다 | 공용 위치에 새로 만들고, 화면마다 가져다 씁니다 |
| 이 화면 전용 | 이 화면에서만 씁니다 | 이 화면의 코드 안에 만듭니다 |

Figma에서 컴포넌트로 만든 덩어리는 코드에서도 컴포넌트여야 합니다. 지시할 때 Figma의 컴포넌트 이름을 그대로 쓰면 디자인과 코드의 이름이 맞춰집니다.

## 2. 같은 것인지 비슷해 보이는 것인지 판단합니다

두 화면의 덩어리가 닮았다고 해서 모두 하나로 합치는 것은 아닙니다. 판단하는 질문은 이것입니다.

"한쪽을 바꾸면 다른 쪽도 반드시 같이 바뀌어야 하는가."

그렇다면 같은 것이므로 하나의 컴포넌트로 만듭니다. 지금은 닮았지만 서로 다르게 바뀔 수 있다면 따로 둡니다. 다른 것을 억지로 하나로 합치면, 나중에 한쪽만 바꾸기 위해 예외 조건이 계속 붙습니다.

## 3. 새 공용 컴포넌트를 만들 때 정할 것

1. 이름. Figma 컴포넌트의 이름과 맞춥니다.
2. 바뀌는 부분. 쓰는 자리마다 달라지는 것(문구, 상태, 아이콘 등)이 props가 됩니다. Figma에서 컴포넌트 속성으로 정한 것과 맞춥니다.
3. 두는 위치. 프로젝트마다 공용 컴포넌트를 두는 폴더 규칙이 있습니다. AI에게 기존 규칙을 따르게 하고, 규칙이 분명하지 않으면 개발자에게 묻습니다.

여러 제품에서 쓸 만한 것이라면 프로젝트 안에 만들지 않고 디자인 시스템에 추가를 요청하는 것이 맞을 수 있습니다. 이 판단은 디자이너가 합니다.

## 4. PR을 올리기 전에: 처음에 말한 목록과 결과를 비교합니다

AI에게 이번 변경에서 새로 만든 컴포넌트와 그것이 쓰이는 위치를 물어서, 1번에서 말한 분류와 비교합니다. 확인할 것은 세 가지입니다.

- 이미 있는 것을 쓰라고 한 자리에 새 컴포넌트가 만들어지지 않았는가
- 공용으로 만들라고 한 것이 한 곳에서 정의되고 여러 화면에서 가져다 쓰이고 있는가
- 말하지 않은 컴포넌트가 새로 생기지 않았는가

## 5. PR 설명에 적습니다

재사용 단위를 PR 설명에 적어 두면, 리뷰하는 개발자가 디자이너의 의도와 구현이 일치하는지 확인할 수 있습니다. 예를 들면 이렇게 적습니다.

```
재사용 단위
- 구성원 카드: 새 공용 컴포넌트. 구성원 목록과 팀 상세에서 함께 사용
- 상태 배지: 디자인 시스템 컴포넌트 사용
- 휴가 요약 영역: 이 화면 전용
```

## AI에게 이렇게 말합니다

- "이 화면의 구성원 카드는 팀 상세 화면의 것과 같은 컴포넌트여야 해. 이미 구현된 것이 있는지 먼저 찾고, 없으면 만들기 전에 어디에 어떤 이름으로 만들지 나에게 확인해줘."
- "새 컴포넌트를 만들기 전에, 비슷한 기존 컴포넌트가 있는지 검색해서 후보를 보여줘."
- "이 변경에서 새로 만든 컴포넌트의 목록과 각각이 쓰이는 위치를 알려줘. 비슷한 기존 컴포넌트가 있으면 함께 알려줘."
- "이 두 화면의 이 영역이 지금 같은 컴포넌트를 쓰고 있는지, 각각 따로 구현되어 있는지 확인해줘."
