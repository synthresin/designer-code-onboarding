# API: 화면이 데이터를 받아오는 방식

화면에 보이는 이름, 숫자, 목록은 화면 코드 안에 적혀 있지 않고 서버에서 받아옵니다. API는 화면이 서버에 데이터를 요청하고 받는 약속된 형식입니다. 디자이너에게 중요한 사실은 하나입니다. 화면에 보여 줄 수 있는 것은 서버가 응답으로 보내 주는 것뿐입니다.

## 요청과 응답

화면은 서버에 요청을 보내고, 서버는 응답을 돌려줍니다.

- 요청에는 무엇에 대해(주소), 어떤 동작을(조회, 생성, 수정, 삭제) 원하는지가 들어 있습니다.
- 응답에는 정해진 형태의 데이터가 들어 있습니다. 보통 JSON이라는 형식의 텍스트입니다.

구성원 한 명의 휴가 정보를 조회한 응답은 예를 들어 이렇게 생겼습니다. 형태를 보여 주기 위한 예시입니다.

```
{
  "name": "김하늘",
  "team": "디자인",
  "remainingDays": 12,
  "requests": [
    { "startDate": "2026-10-12", "days": 2, "status": "승인 대기" },
    { "startDate": "2026-11-02", "days": 1, "status": "승인" }
  ]
}
```

어떤 주소에 어떤 요청을 보내면 어떤 형태의 응답이 오는지가 미리 약속되어 있고, 화면 쪽 개발자와 서버 쪽 개발자가 이 약속을 기준으로 따로 일합니다. 이 약속이 API입니다.

## 디자이너에게 의미하는 것

**응답에 없는 정보는 뷰만 고쳐서는 보여 줄 수 없습니다.** 위 응답에는 입사일이 없습니다. 시안에 입사일이 있다면, 서버가 입사일을 응답에 넣어 주도록 API가 바뀌어야 합니다. 이것은 개발자의 일입니다. 반대로 응답에 이미 있는데 화면에 쓰지 않고 있던 정보는 뷰만 고쳐서 보여 줄 수 있습니다.

**응답의 형태가 화면의 구조와 연결됩니다.** 위 응답에서 requests는 여러 건이 들어 있는 목록입니다. 화면에서는 반복되는 행이나 카드가 됩니다. 한 건만 오는 값과 여러 건이 오는 목록은 화면에서 다르게 다뤄집니다.

**요청은 시간이 걸리고 실패할 수 있습니다.** 응답이 오기 전의 로딩 상태, 응답이 비어 있는 상태, 요청이 실패한 상태가 스펙에 있는 이유가 이것입니다. 코드에서 이 상태들은 요청을 보내는 지점에서 생깁니다.

**데이터를 바꾸는 요청은 조회와 성격이 다릅니다.** 조회는 여러 번 해도 아무것도 바뀌지 않지만, 생성과 수정과 삭제는 서버의 데이터를 실제로 바꿉니다. 저장 버튼의 동작을 고치는 일은 뷰의 변경이 아닙니다.

## 이미 들어오는 데이터인지 확인하기

화면 구성 작업을 시작할 때 가장 먼저 확인할 것은 "시안에 필요한 정보가 지금 이 화면이 받는 응답에 모두 있는가"입니다. 모두 있으면 뷰만 고쳐서 끝낼 수 있습니다. 없는 것이 있으면 그 목록이 개발자에게 보낼 요청이 됩니다.

코드에는 응답의 형태를 적어 둔 정의가 있는 경우가 많아서, AI가 그것을 읽고 어떤 값이 들어오는지 알려 줄 수 있습니다.

## AI에게 이렇게 말합니다

- "이 화면이 서버에서 받아오는 데이터에 어떤 값들이 있는지 목록으로 알려줘. 코드는 수정하지 마."
- "내 시안에는 입사일과 직급이 필요해. 이 화면이 이미 받고 있는 데이터에 있는지 확인해줘."
- "없는 값은 API를 고치지 말고, 개발자에게 보낼 요청으로 정리해줘. 어떤 화면에서 어떤 값이 왜 필요한지 적어줘."
