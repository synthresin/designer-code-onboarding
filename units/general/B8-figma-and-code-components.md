# Figma 컴포넌트와 코드 컴포넌트의 대응: variant와 props

코드에도 컴포넌트가 있고, Figma의 컴포넌트와 같은 목적을 가집니다. 한 번 정의하고 여러 곳에서 가져다 씁니다. Figma에서 컴포넌트의 속성을 고르는 것은, 코드에서 컴포넌트에 props라는 값을 넘기는 것에 대응합니다.

## 정의와 사용

| Figma | 코드 |
| --- | --- |
| 메인 컴포넌트 | 컴포넌트를 정의한 코드. 파일 하나 또는 폴더 하나입니다 |
| 인스턴스 | 다른 화면 코드에서 그 컴포넌트를 가져다 쓴 자리 |
| 메인 컴포넌트를 고치면 모든 인스턴스가 바뀝니다 | 정의한 코드를 고치면 그것을 쓰는 모든 화면이 바뀝니다 |

세 번째 줄이 중요합니다. 화면 하나의 버튼을 바꾸려는데 AI가 버튼 컴포넌트를 정의한 코드를 고치면, 그 버튼을 쓰는 모든 화면이 바뀝니다. 수정을 요청할 때 "이 화면에서 쓰인 자리만" 바꾸는 것인지, "컴포넌트 자체를" 바꾸는 것인지를 구분해서 말해야 합니다. 디자인 시스템 패키지의 컴포넌트는 제품 레포에서 정의를 고칠 수 없고, 쓰는 자리에서 props만 바꿀 수 있습니다.

## props: 컴포넌트에 넘기는 값

props는 컴포넌트를 쓰는 자리에서 그 컴포넌트에 넘기는 값입니다. 아래는 구조를 보여 주기 위한 예시이고, 실제 컴포넌트의 props 이름과는 다릅니다.

```
<Button variant="primary" size="large" disabled>
  신청하기
</Button>
```

여기서 variant, size, disabled가 props입니다. Figma의 속성 패널에서 고르는 값들과 대응합니다.

| Figma의 컴포넌트 속성 | 코드의 props |
| --- | --- |
| variant 속성 (예: Type = Primary) | 정해진 값 중 하나를 고르는 props |
| 켜고 끄는 속성 (예: Disabled) | 참 또는 거짓인 props |
| 텍스트 속성 | 글자를 넘기는 props, 또는 태그 사이에 적는 내용 |
| 인스턴스 교체 속성 (예: 아이콘) | 다른 컴포넌트를 넘기는 props |

## 대응이 맞지 않는 지점

1. **코드에서는 열어 둔 것만 바꿀 수 있습니다.** Figma에서는 인스턴스의 색을 직접 바꾸거나 인스턴스를 분리해서 마음대로 고칠 수 있습니다. 코드의 컴포넌트는 props로 열어 둔 것만 바꿀 수 있습니다. 버튼 컴포넌트에 색을 넘기는 props가 없다면, 그 버튼의 색을 쓰는 자리에서 임의로 바꾸는 것은 정해진 방법이 아닙니다. AI가 억지로 덮어쓰는 코드를 만들 수 있지만, 그것은 Figma에서 인스턴스를 분리한 것과 같은 결과를 낳습니다. 디자인 시스템이 업데이트되어도 그 자리는 따라가지 않습니다.
2. **이름과 값이 Figma와 다를 수 있습니다.** Figma에서 Type = Primary인 속성이 코드에서는 다른 이름과 다른 값으로 되어 있을 수 있습니다. 실제 대응은 플랫폼 단위(B9)에서 확인합니다.
3. **Figma에 있는 variant가 코드에 없거나, 그 반대일 수 있습니다.** 한쪽에만 있는 것을 발견하면 디자인 시스템의 차이로 기록해 둘 가치가 있습니다.

## 필요한 것이 컴포넌트에 없을 때

원하는 모양이 기존 컴포넌트의 props로 만들어지지 않으면, 선택지는 세 가지입니다.

1. 기존 props의 조합으로 다시 디자인합니다.
2. 디자인 시스템에 props나 variant를 추가해 달라고 요청합니다.
3. 그 화면에만 쓰는 컴포넌트를 새로 만듭니다.

어느 쪽으로 할지는 디자이너가 정할 일입니다. AI가 묻지 않고 3번이나 억지로 덮어쓰는 방법을 택하지 않도록, 지시할 때 미리 말해 둡니다.

## AI에게 이렇게 말합니다

- "이 화면에서 쓰인 Button의 props가 각각 무엇을 정하는지, 고를 수 있는 값이 무엇인지 알려줘."
- "컴포넌트 정의는 고치지 말고, 이 화면에서 쓰인 자리의 props만 바꿔줘."
- "기존 컴포넌트의 props로 안 되는 부분이 있으면 스타일을 덮어쓰지 말고 멈춰서 나에게 알려줘."
