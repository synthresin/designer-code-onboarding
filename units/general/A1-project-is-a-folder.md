# 개발 프로젝트는 폴더이고 코드는 텍스트 파일이다

개발 프로젝트 하나는 내 컴퓨터의 폴더 하나입니다. 그 폴더 안에 있는 코드 파일은 모두 글자만 들어 있는 텍스트 파일입니다. 이후의 모든 내용이 이 두 가지를 전제로 합니다.

## 프로젝트는 폴더입니다

"프로젝트를 연다"는 말은 폴더 하나를 연다는 뜻입니다. 그 폴더 안에 하위 폴더와 파일이 수백 개에서 수천 개 들어 있습니다. Finder에서 보이는 보통 폴더와 다르지 않습니다.

폴더의 구조에는 의미가 있습니다. 화면 코드는 이 폴더, 이미지는 저 폴더처럼 역할에 따라 나뉘어 있고, 파일의 위치와 이름을 보고 그 파일이 무슨 일을 하는지 짐작할 수 있습니다. 어떤 폴더가 어떤 역할인지는 프로젝트마다 다릅니다.

## 코드는 텍스트 파일입니다

코드 파일은 글자만 들어 있는 파일입니다. 메모장 같은 텍스트 편집기로 열면 내용이 그대로 보이고, 글자를 고쳐서 저장하면 코드를 고친 것입니다. 특별한 프로그램이 있어야만 열리는 파일이 아닙니다.

코드가 화면이 되는 것은, 어떤 프로그램이 이 텍스트 파일들을 읽어서 그 내용대로 동작하기 때문입니다. 그래서 "코드를 고친다"는 것은 텍스트 파일의 글자를 바꾼다는 뜻이고, "실행한다"는 것은 프로그램에게 그 파일들을 읽고 동작하라고 시킨다는 뜻입니다.

AI 코딩 앱이 하는 일도 이것입니다. AI는 폴더 안의 텍스트 파일을 읽고, 글자를 고치고, 프로그램을 실행시킵니다.

## 레포는 변경 기록이 관리되는 폴더입니다

레포(repository, 저장소)는 git이라는 도구가 변경 기록을 관리하고 있는 프로젝트 폴더입니다. 폴더 안의 파일이 언제 누구에 의해 어떻게 바뀌었는지가 기록됩니다. 회사에서 다루는 프로젝트는 레포라고 생각하면 됩니다. git의 구조는 단위 B1에서 다룹니다.

레포의 원본은 GitHub에 있고, 내 컴퓨터에는 그 복사본을 받아서 작업합니다. 내 컴퓨터의 복사본을 고쳐도 GitHub에 있는 원본이나 다른 사람의 복사본은 바뀌지 않습니다.

## Figma와 비교하면

| | Figma | 코드 프로젝트 |
| --- | --- | --- |
| 작업 대상 | 파일 하나 | 폴더 하나와 그 안의 많은 텍스트 파일 |
| 있는 곳 | 클라우드에 하나만 있고 모두가 그것을 엽니다 | GitHub에 원본이 있고 각자 자기 컴퓨터에 복사본을 받습니다 |
| 다른 사람의 변경 | 실시간으로 보입니다 | 받아오는 작업을 해야 내 복사본에 반영됩니다 |

가장 큰 차이는 세 번째 줄입니다. Figma에서는 모두가 같은 파일을 보지만, 코드에서는 각자 자기 복사본에서 작업한 뒤 합칩니다.

## AI에게 이렇게 말합니다

- "이 프로젝트의 최상위 폴더들이 각각 무슨 역할인지 한 줄씩 설명해줘. 코드는 수정하지 마."
- "이 파일이 무슨 일을 하는 파일인지 설명해줘."
