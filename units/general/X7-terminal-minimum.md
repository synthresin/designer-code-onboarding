# 터미널을 직접 쓰고 싶은 사람을 위한 최소 사용법

이 과정에서 터미널 명령은 AI가 실행하므로 터미널을 직접 쓸 필요는 없습니다. 그래도 AI가 무엇을 하고 있는지 직접 확인해 보고 싶거나, 간단한 확인은 스스로 하고 싶은 사람을 위해 최소한의 사용법을 적습니다. 여기에 있는 명령은 대부분 아무것도 바꾸지 않는 읽기 전용 명령입니다.

## 터미널이 하는 일

터미널은 글자로 명령을 입력해서 컴퓨터에 일을 시키는 창입니다. Finder에서 폴더를 열고 파일을 여는 일을, 마우스 대신 글자로 합니다. AI 코딩 앱이 명령을 실행할 때 쓰는 것도 이것입니다.

## 1. 현재 위치를 확인합니다

터미널은 항상 어떤 폴더 안에 있습니다. 명령은 그 폴더를 기준으로 실행됩니다. 명령이 예상대로 동작하지 않는 가장 흔한 이유는 다른 폴더에 있기 때문입니다.

| 명령 | 하는 일 |
| --- | --- |
| `pwd` | 지금 있는 폴더의 경로를 보여 줍니다 |
| `ls` | 지금 폴더에 있는 파일과 폴더의 목록을 보여 줍니다 |
| `cd 폴더이름` | 그 폴더로 들어갑니다 |
| `cd ..` | 한 단계 위의 폴더로 나갑니다 |

## 2. 명령의 구조를 읽습니다

명령은 띄어쓰기로 나뉜 단어들입니다. 맨 앞이 프로그램의 이름이고, 뒤에 붙는 것이 그 프로그램에 넘기는 지시입니다.

```
git log --oneline
```

`git`이 프로그램이고, `log`가 시킬 일이고, `--oneline`이 방식을 정하는 옵션입니다. 줄표로 시작하는 단어는 옵션입니다.

## 3. git의 상태를 확인하는 읽기 전용 명령

아래 명령은 아무것도 바꾸지 않으므로 언제든 실행해도 됩니다.

| 명령 | 하는 일 |
| --- | --- |
| `git status` | 지금 브랜치, 바뀐 파일, 커밋하지 않은 변경을 보여 줍니다 |
| `git branch` | 내 컴퓨터에 있는 브랜치 목록과 지금 있는 브랜치를 보여 줍니다 |
| `git log --oneline` | 커밋 기록을 한 줄씩 보여 줍니다 |
| `git diff` | 커밋하지 않은 변경의 내용을 보여 줍니다 |

결과가 길면 화면이 멈춘 것처럼 보이고 맨 아래에 `:`이 표시됩니다. 화살표 키로 내려 볼 수 있고, `q`를 누르면 빠져나옵니다.

## 4. 실행 중인 것을 멈춥니다

개발 서버처럼 계속 실행되는 프로그램은 `Ctrl + C`로 멈춥니다. 터미널이 입력을 받지 않고 멈춰 있는 것처럼 보일 때도 대개 무언가가 실행 중인 것이고, `Ctrl + C`로 빠져나올 수 있습니다.

## 5. 편하게 쓰는 방법

- 위쪽 화살표 키를 누르면 이전에 입력한 명령이 다시 나옵니다.
- 폴더나 파일 이름을 몇 글자 입력하고 `Tab`을 누르면 나머지가 자동으로 채워집니다.

## 조심할 것

- 무엇을 하는지 모르는 명령을 붙여 넣어 실행하지 않습니다. 모르는 명령은 AI에게 먼저 설명을 요청합니다.
- `rm`은 파일을 지우는 명령이고, 휴지통을 거치지 않으므로 되돌릴 수 없습니다.
- `sudo`로 시작하는 명령은 컴퓨터 전체에 대한 권한으로 실행됩니다. 이 과정의 작업에는 필요하지 않습니다.
- 변경을 만드는 git 명령(커밋, 푸시, 브랜치 전환 등)은 직접 입력하기보다 AI에게 맡기고, 여기의 읽기 전용 명령으로 결과를 확인하는 방식을 권합니다.

## AI에게 이렇게 말합니다

- "방금 실행한 명령을 단어별로 나눠서 각각이 무슨 뜻인지 설명해줘."
- "내가 터미널에서 직접 확인해 보고 싶어. 지금 상태를 확인하는 읽기 전용 명령을 알려줘."
