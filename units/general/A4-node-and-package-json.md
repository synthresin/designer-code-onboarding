# node와 package.json: 프로젝트가 실행되는 방식과 외부 패키지를 가져다 쓰는 방식

웹 프로젝트를 내 컴퓨터에서 띄우려면 node라는 프로그램이 필요하고, 프로젝트가 가져다 쓰는 외부 코드의 목록은 package.json이라는 파일에 적혀 있습니다. 설치와 실행은 AI가 하지만, 이 두 가지가 무엇인지는 알아야 화면이 뜨지 않을 때 무슨 일인지 이해할 수 있습니다.

## node는 프로젝트의 도구들을 실행시키는 프로그램입니다

웹 화면의 코드는 JavaScript 계열의 언어로 쓰여 있습니다. node는 이 언어로 쓰인 프로그램을 브라우저 밖, 즉 내 컴퓨터에서 실행시키는 프로그램입니다. 웹 프로젝트를 띄우는 개발 서버와 코드를 검사하는 도구들이 node 위에서 동작합니다.

node에는 버전이 있고, 프로젝트마다 요구하는 버전이 정해져 있습니다. 버전이 맞지 않으면 설치나 실행이 실패할 수 있습니다. 버전을 맞추는 일은 셋업 절차가 처리하므로 직접 다룰 일은 없습니다.

## 개발 서버는 내 컴퓨터에서 화면을 띄워 주는 프로그램입니다

개발 서버를 실행하면 브라우저에서 localhost로 시작하는 주소로 프로젝트의 화면을 볼 수 있습니다. localhost는 내 컴퓨터 자신을 가리키는 주소라서, 이 화면은 나만 볼 수 있습니다.

알아 둘 점은 두 가지입니다.

- 개발 서버는 실행되고 있는 동안에만 화면을 보여 줍니다. 서버를 끄거나 앱을 닫으면 그 주소는 열리지 않습니다. 화면이 열리지 않으면 먼저 서버가 실행 중인지 확인합니다.
- 서버가 실행 중일 때 코드를 고치면 브라우저의 화면에 변경이 곧바로 반영됩니다.

## package.json은 프로젝트가 가져다 쓰는 외부 패키지의 목록입니다

프로젝트의 최상위 폴더에 package.json 파일이 있습니다. 이 파일에는 주로 두 가지가 적혀 있습니다.

- 이 프로젝트가 가져다 쓰는 외부 패키지의 이름과 버전. 패키지는 다른 사람이나 다른 팀이 만들어서 배포한 코드 묶음입니다. 회사의 디자인 시스템도 이런 패키지 하나로 배포되어 여러 프로젝트에 설치됩니다.
- 이 프로젝트에서 자주 쓰는 명령에 붙인 이름. 예를 들어 개발 서버를 실행하는 명령이 여기에 정의되어 있습니다.

패키지마다 버전 숫자가 적혀 있다는 점이 중요합니다. 디자인 시스템 패키지가 새 버전으로 업데이트되어도, 어떤 프로젝트의 package.json에 예전 버전이 적혀 있으면 그 프로젝트는 예전 버전을 씁니다. Figma 라이브러리에서 컴포넌트를 고쳤는데 제품 화면에는 반영되지 않았다면, 그 프로젝트가 아직 예전 버전의 패키지를 쓰고 있을 수 있습니다.

## 설치된 패키지는 node_modules 폴더에 있습니다

package.json은 목록일 뿐이고, 패키지의 실제 코드는 설치 명령을 실행해야 내 컴퓨터에 받아집니다. 받아진 코드는 프로젝트 안의 node_modules 폴더에 들어갑니다. 이 폴더는 파일이 매우 많고, 직접 고치지 않으며, GitHub에 올리지 않습니다. 각자 자기 컴퓨터에서 설치 명령으로 만듭니다.

그래서 레포를 처음 받았을 때와, 다른 사람이 package.json을 바꾼 변경을 받아왔을 때는 설치 명령을 다시 실행해야 합니다. 최신 내용을 받은 뒤에 화면이 뜨지 않는다면 이 경우일 수 있습니다.

## Figma와 비교하면

| Figma | 코드 프로젝트 |
| --- | --- |
| 팀 라이브러리 | 패키지 |
| 라이브러리를 게시합니다 | 패키지의 새 버전을 배포합니다 |
| 파일에서 라이브러리 업데이트를 수락합니다 | package.json의 버전 숫자를 올리고 다시 설치합니다 |

대응이 맞지 않는 지점이 있습니다. Figma에서는 업데이트 알림이 뜨고 수락하면 끝나지만, 코드에서는 버전을 올리는 것이 변경 한 건이고, 올린 뒤에 기존 화면이 깨지지 않는지 확인하는 작업이 따릅니다. 그래서 프로젝트마다 쓰는 버전이 다를 수 있습니다.
