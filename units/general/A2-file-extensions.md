# 확장자로 파일의 역할 구분하기

코드 파일은 모두 텍스트 파일이지만, 어떤 언어로 쓰였고 어떤 프로그램이 읽는지는 파일마다 다릅니다. 파일 이름 끝의 확장자가 그것을 알려 줍니다. 언어의 문법을 알 필요는 없고, 확장자를 보고 그 파일의 역할을 구분할 수 있으면 됩니다.

## 왜 구분할 수 있어야 하나요

AI가 작업을 마치면 어떤 파일을 고쳤는지 목록이 나옵니다. 문구 하나를 바꿔 달라고 했는데 설정 파일이 함께 바뀌어 있다면, 의도하지 않은 변경이 들어간 것입니다. 확장자를 구분할 수 있으면 이런 경우를 알아차릴 수 있습니다.

## 웹 프로젝트에서 자주 보이는 확장자

| 확장자 | 역할 | 디자이너와의 관계 |
| --- | --- | --- |
| .tsx, .jsx | 화면을 기술하는 코드입니다. 화면의 구조와 동작이 함께 들어 있습니다 | 가장 자주 보고 고치게 되는 파일입니다 |
| .ts, .js | 화면이 아닌 로직 코드입니다. 데이터 처리, 계산, 서버와의 통신 등이 들어 있습니다 | 읽을 일은 있지만 고칠 일은 드뭅니다 |
| .css, .scss | 색, 간격, 크기 같은 스타일을 기술합니다 | 프로젝트에 따라 스타일을 이 파일에 쓰기도 하고 화면 코드 안에 쓰기도 합니다 |
| .json | 설정이나 데이터를 정해진 형식으로 적은 파일입니다 | 프로젝트 설정, 번역 문구, 토큰 값 등이 이 형식으로 있을 수 있습니다 |
| .md | 사람이 읽는 문서입니다. 지금 읽고 있는 이 글도 .md 파일입니다 | 프로젝트의 설명서와 AI에게 주는 지침이 이 형식입니다 |
| .svg, .png | 이미지입니다. svg는 텍스트로 쓰인 이미지입니다 | 아이콘과 일러스트입니다 |
| .env | 비밀 값과 환경 설정이 들어 있는 파일입니다 | 열어 보거나 다른 곳에 붙여 넣지 않습니다 |

.ts와 .js는 같은 계열의 언어이고, .ts 쪽은 값의 종류를 미리 적어 두는 규칙이 추가된 것입니다. .tsx와 .jsx는 각각에 화면을 기술하는 문법이 더해진 것입니다. 이 과정에서는 이 정도의 구분이면 충분합니다.

## 다른 플랫폼의 확장자

웹이 아닌 플랫폼은 다른 언어를 씁니다. 예를 들어 안드로이드와 Jetpack Compose 프로젝트의 코드는 .kt 파일(Kotlin 언어)입니다. 언어는 다르지만 "화면을 기술하는 파일, 로직 파일, 설정 파일이 따로 있다"는 구조는 같습니다.

## 이름에서 알 수 있는 것

확장자 외에 파일 이름과 폴더 이름도 단서가 됩니다. 이름에 test나 spec이 들어 있으면 코드가 맞게 동작하는지 자동으로 확인하는 테스트 파일이고, config가 들어 있으면 설정 파일입니다. 이름이 점으로 시작하는 파일과 폴더(.git, .github 등)는 도구가 쓰는 것으로, 직접 고칠 일이 없습니다.

## AI에게 이렇게 말합니다

- "방금 고친 파일의 목록을 보여주고, 각 파일이 화면 코드인지, 스타일인지, 로직인지, 설정인지 구분해줘."
- "이 프로젝트에서 스타일은 어떤 파일에 어떤 방식으로 쓰여 있는지 알려줘."
