# 화면은 부모와 자식의 트리로 기술된다

코드에서 화면은 2D 이미지로 기술되지 않고, 요소가 다른 요소를 품는 구조로 기술됩니다. 품는 쪽을 부모, 안에 들어 있는 쪽을 자식이라고 하고, 이 구조 전체를 트리라고 부릅니다. Figma에서 프레임 안에 프레임을 넣고 오토레이아웃을 거는 것과 같은 사고방식입니다.

## 좌표가 아니라 구조로 기술합니다

화면 코드에는 "이 버튼은 왼쪽에서 120, 위에서 340 위치"처럼 좌표를 적지 않습니다. 대신 "카드 안에 세로로 쌓는 묶음이 있고, 그 묶음 안에 제목, 본문, 버튼이 순서대로 있다"처럼 적습니다. 각 요소의 위치는 부모가 자식을 어떻게 배치하는지에 따라 정해집니다.

아래는 구조를 보여 주기 위한 예시이고, 실제 컴포넌트 이름과는 다릅니다.

```
<Card>
  <Stack direction="vertical" gap="8">
    <Title>휴가 신청</Title>
    <Text>남은 휴가 12일</Text>
    <Button>신청하기</Button>
  </Stack>
</Card>
```

들여쓰기가 부모와 자식의 관계입니다. Card가 Stack의 부모이고, Stack이 Title, Text, Button의 부모입니다. Figma의 레이어 패널에서 보는 들여쓰기와 같은 뜻입니다.

## 배치는 부모가 정합니다

위 예시에서 제목, 본문, 버튼 사이의 간격 8은 각 자식에 적혀 있지 않고 부모인 Stack에 적혀 있습니다. 방향, 간격, 정렬, 안쪽 여백은 부모의 속성입니다.

이 점을 알면 수정 요청이 정확해집니다. "버튼을 아래로 8만큼 내려줘"는 좌표로 생각한 요청이고, "이 묶음의 자식 사이 간격을 8에서 16으로 바꿔줘"는 구조로 생각한 요청입니다. 앞의 요청을 받은 AI는 버튼 하나에만 여백을 추가할 수 있고, 그러면 구조와 맞지 않는 예외가 코드에 하나 생깁니다.

## 화면 전체도 같은 구조입니다

페이지 전체도 같은 방식입니다. 페이지가 머리글, 본문 영역, 옆 메뉴를 품고, 본문 영역이 카드 여러 개를 품고, 카드가 다시 제목과 버튼을 품습니다. 큰 조각이 작은 조각을 품는 구조가 화면의 가장 바깥부터 가장 안쪽까지 이어집니다.

그래서 화면의 한 부분을 가리킬 때는 바깥에서 안쪽으로 따라가며 말할 수 있습니다. "휴가 신청 페이지의 본문 영역에 있는 첫 번째 카드의 버튼"처럼 말하면 AI가 코드에서 같은 경로로 찾아갑니다.

## Figma와 비교하면

| Figma | 코드 |
| --- | --- |
| 프레임 안의 프레임 | 부모 요소 안의 자식 요소 |
| 레이어 패널의 들여쓰기 | 코드의 들여쓰기 |
| 오토레이아웃의 방향, 간격, 패딩, 정렬 | 부모 요소의 배치 속성 |
| 채우기(Fill), 내용에 맞춤(Hug), 고정(Fixed) | 자식 요소의 크기 속성 |

대응이 맞지 않는 지점이 있습니다. Figma에서는 오토레이아웃을 걸지 않은 프레임 안에 요소를 아무 좌표에나 놓을 수 있습니다. 코드에서는 구조로 배치하는 것이 기본이고, 좌표로 직접 놓는 것은 다른 요소 위에 겹쳐 띄우는 경우처럼 예외적인 상황에서만 씁니다. 오토레이아웃 없이 그린 시안은 코드로 옮길 때 구조를 다시 정해야 합니다.

## AI에게 이렇게 말합니다

- "이 화면의 구조를 부모와 자식의 트리로 보여줘. 각 요소가 어떤 컴포넌트인지도 적어줘. 코드는 수정하지 마."
- "이 카드 안에서 제목과 본문 사이의 간격은 어느 요소의 어떤 속성으로 정해져 있어?"
- "버튼 하나에만 여백을 추가하지 말고, 이 묶음의 자식 사이 간격을 바꿔줘."
