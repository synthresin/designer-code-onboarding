# 이 과정이 다루는 것과 다루지 않는 것

이 과정은 디자이너가 AI 코딩 앱으로 회사 코드베이스에서 자신의 디자인을 직접 구현할 수 있게 하는 과정입니다. 명령어를 외우는 과정이 아니고, 개발자가 되는 과정도 아닙니다. AI에게 작업을 지시하고, 결과가 맞는지 판단하고, 문제가 생겼을 때 무슨 일인지 설명하는 데 필요한 구조를 이해하는 과정입니다.

## 다루는 것

과정은 네 개의 작업 범위로 나뉩니다. 앞의 작업 범위를 마친 뒤에 다음으로 넘어갑니다.

| 작업 범위 | 할 수 있게 되는 작업 |
| --- | --- |
| 읽기 | 프로젝트를 내 컴퓨터에서 띄우고, 내가 디자인한 화면이 코드의 어디에 있는지 찾습니다. 코드는 고치지 않습니다 |
| 뷰 수정 | 문구, 간격, 색처럼 데이터와 로직에 영향이 없는 변경을 올려서 실제 제품에 반영되게 합니다 |
| 화면 구성 | 이미 화면에 들어오고 있는 데이터를 그대로 쓰면서 화면의 구성을 바꾸거나 새 화면 조각을 만듭니다 |
| 로직 포함 | 개발자와 미리 합의한 범위 안에서, 화면과 그 화면에만 쓰이는 작은 로직을 함께 고칩니다 |

각 작업 범위의 끝에는 마무리 과제가 있습니다. 마무리 과제는 연습 문제가 아니라 실제 작업 한 건입니다.

## 다루지 않는 것

- 명령어 암기. 터미널 명령은 AI가 실행합니다. 여러분은 그 명령이 무엇을 하는지 한 문장으로 설명을 듣고 진행 여부를 결정합니다.
- 프로그래밍 언어의 문법. 코드를 한 줄씩 직접 쓰는 방법은 가르치지 않습니다.
- 서버, 데이터베이스, 배포. 이 영역은 개발자의 일로 남습니다. 궁금한 사람을 위한 심화 글은 따로 있습니다.

## 미리 알아 둘 것

push나 pull 같은 명령을 쓸 줄 아는 것은 Figma에서 오토레이아웃을 쓸 줄 아는 것과 같은 수준의 기능 사용법입니다. 그것을 할 줄 안다고 해서 개발을 아는 것은 아닙니다. 이 과정에서 중요하게 다루는 것은 그 명령들이 다루는 구조입니다. 코드가 어떤 파일들로 이루어지는지, 변경이 어떻게 기록되고 합쳐지는지, 화면이 어떤 부모와 자식으로 이루어지는지, 디자인 시스템이 코드에서 어떻게 쓰이는지입니다.

이 구조를 이해하면 AI에게 "이 영역은 저 화면과 같은 컴포넌트를 써야 해"처럼 정확하게 지시할 수 있고, AI가 한 작업이 의도와 맞는지 확인할 수 있습니다. 구조를 모르면 AI가 만든 결과를 그대로 받아들일 수밖에 없습니다.
