# 디자이너 코드 협업 온보딩

디자이너가 AI 코딩 앱(Claude Code 앱, Codex 앱 등)으로 회사 코드베이스에서 자신의 디자인을 직접 구현할 수 있게 하는 온보딩 과정입니다.

명령어를 외우게 하는 과정이 아닙니다. AI에게 작업을 지시하고, 결과가 맞는지 판단하고, 문제가 생겼을 때 무슨 일인지 설명하는 데 필요한 구조를 이해하게 하는 과정입니다. 터미널 명령은 AI가 실행합니다.

## 시작하는 방법

AI 코딩 앱에서 아무 폴더나 하나 열고, 아래 문장을 그대로 붙여 넣습니다.

```
https://github.com/synthresin/designer-code-onboarding 이 저장소를 받아서 온보딩 해줘
```

AI가 저장소를 내 컴퓨터에 받고, 첫 단위부터 설명과 실습을 진행합니다. 다음에 이어서 할 때는 받아 둔 `designer-code-onboarding` 폴더를 앱에서 열고 "온보딩 이어서 할게"라고 말합니다.

저장소를 직접 받아도 됩니다. 이 페이지의 Code 버튼에서 ZIP으로 내려받아 압축을 풀고, 그 폴더를 앱에서 연 뒤 "온보딩 시작할게"라고 말합니다.

## AI 도구에게

이 저장소로 온보딩을 요청받았다면 `AGENTS.md`를 읽고 그 지시를 따르세요.

## 과정의 구성

과정은 네 개의 작업 범위로 나뉩니다.

| 작업 범위 | 할 수 있게 되는 작업 |
| --- | --- |
| 읽기 | 프로젝트를 내 컴퓨터에서 띄우고, 내가 디자인한 화면이 코드의 어디에 있는지 찾습니다 |
| 뷰 수정 | 문구, 간격, 색처럼 데이터와 로직에 영향이 없는 변경을 올립니다 |
| 화면 구성 | 이미 화면에 들어오고 있는 데이터를 그대로 쓰면서 화면의 구성을 바꿉니다 |
| 로직 포함 | 개발자와 합의한 범위 안에서 화면과 작은 로직을 함께 고칩니다 |

이 저장소에는 어느 회사에서나 같은 내용인 일반 단위와, 프로젝트 없이 할 수 있는 git 실습이 들어 있습니다. 회사의 디자인 시스템과 레포에 대한 단위는 회사마다 내용이 달라서 제목만 있습니다. 그래서 이 저장소만으로는 개념 단위와 git 실습까지 진행할 수 있고, 실제 프로젝트에서 화면을 띄우고 고치는 부분은 회사에 적용한 뒤에 진행할 수 있습니다.

## 들어 있는 것

- `PRINCIPLES.md`: 이 온보딩의 원칙
- `AGENTS.md`: AI 도구가 이 폴더에서 가장 먼저 읽는 파일. 온보딩을 받으려는 요청인지, 자료를 고치려는 요청인지에 따라 읽을 파일을 알려 줍니다
- `units/general/`: 일반 단위
- `units/INDEX.md`: 전체 단위 목록
- `exercises/`: 직접 해 보는 실습
- `paths/`: 읽는 순서
- `skills/`: 온보딩을 진행하는 지침과 디자이너용 작업 규칙
- `requests/`: 개발자에게 셋업 환경과 디자이너 작업 범위를 채워 달라고 요청하는 양식과, 사내 레포를 읽을 수 있는 AI에게 주는 작업 지시
- `ADOPTING.md`: 이 과정을 회사에 적용하는 방법
- `AUTHORING.md`: 자료를 쓰고 고치는 규칙
- `DECISIONS.md`: 이 과정을 설계하면서 내린 결정과 그 이유, 남은 일

## 회사에 적용하는 방법

`ADOPTING.md`에 필요한 역할, 단계, 단계마다 끝났는지 확인하는 방법이 있습니다. AI 코딩 앱에서 이 폴더를 열고 "우리 회사에 적용하고 싶어"라고 말하면 AI가 그 문서를 따라 안내합니다.
