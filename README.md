# 디자이너 코드 협업 온보딩

디자이너가 AI 코딩 앱(Claude Code 앱, Codex 앱 등)으로 회사 코드베이스에서 자신의 디자인을 직접 구현할 수 있게 하는 온보딩 자료와, 그 자료를 만드는 방법입니다.

명령어를 외우게 하는 과정이 아닙니다. AI에게 작업을 지시하고, 결과가 맞는지 판단하고, 문제가 생겼을 때 무슨 일인지 설명하는 데 필요한 구조를 이해하게 하는 과정입니다.

## 들어 있는 것

- `PRINCIPLES.md`: 이 온보딩의 원칙
- `AGENTS.md`: 설계 방법과 글을 쓰는 규칙. AI 도구로 이 폴더에서 작업할 때 먼저 읽게 합니다
- `units/general/`: 어느 회사에서나 같은 내용인 일반 단위
- `units/INDEX.md`: 전체 단위 목록. 회사마다 따로 써야 하는 단위는 제목만 있습니다
- `paths/`: 읽는 순서의 견본
- `requests/`: 개발자에게 셋업 환경을 채워 달라고 요청하는 양식과, 사내 레포를 읽을 수 있는 AI에게 주는 작업 지시
- `skills/README.md`: 온보딩 진행 스킬과 디자이너용 작업 규칙 스킬의 설계

## 회사에 적용하는 방법

1. 이 레포를 회사 안으로 복사합니다.
2. `.gitignore`에서 `company/` 줄을 지우고 `company/` 폴더를 만듭니다.
3. `company/CONTEXT.md`에 회사의 맥락을 적습니다. 디자인 시스템 패키지의 이름, 연습 레포, 제품 레포, 쓰는 AI 코딩 앱, 정해진 규칙 등입니다.
4. 개발자에게 `requests/setup-request.md`를 전달해 레포별 셋업 환경을 채워 받습니다.
5. 사내 레포를 읽을 수 있는 AI에게 `requests/repo-reading-brief.md`를 지시문으로 주어 플랫폼 단위와 레포 단위를 `company/units/` 아래에 쓰게 합니다.
6. `company/paths/`에 실제 레포 이름으로 경로를 둡니다.

회사 안의 사본에서는 `company/` 밖의 파일을 고치지 않습니다. 일반 단위나 방법을 고칠 일이 생기면 이 공개 레포에서 고치고 회사 사본으로 받아옵니다. 그래야 두 곳의 내용이 서로 달라지지 않습니다.
