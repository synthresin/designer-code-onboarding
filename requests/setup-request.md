# 개발자에게 드리는 요청: 셋업 환경 채우기

디자이너가 AI 코딩 앱(Claude Code 앱, Codex 앱)으로 이 레포에서 작업할 수 있도록 온보딩 자료를 만들고 있습니다. 셋업 환경은 개발자분들이 가장 정확히 아시는 부분이라, 아래 빈칸만 채워 주시기를 부탁드립니다.

작성 방법: 레포마다 이 파일을 복사해서 `company/requests/setup-(레포 이름).md`로 저장하고, "답:" 뒤에 적어 주세요. 명령은 복사해서 그대로 실행할 수 있는 형태로 적어 주세요. 디자이너는 명령을 직접 입력하지 않고 AI가 실행합니다. 해당 사항이 없으면 "없음"이라고 적어 주세요.

- 레포 이름:
- 작성자:
- 작성일:

## 1. 설치해야 하는 것

1-1. 필요한 node 버전과, 그 버전이 적혀 있는 파일의 경로
답:

1-2. node를 설치하는 사내 표준 방법(nvm 등)과 설치 명령
답:

1-3. 패키지 매니저의 종류(npm, yarn, pnpm 등)와 버전
답:

1-4. 그 밖에 미리 설치해야 하는 도구
답:

## 2. 권한과 인증

2-1. 디자이너 계정에 필요한 GitHub 권한(조직, 팀, 레포)과 신청 방법
답:

2-2. 사내 패키지 저장소 인증 방법(디자인 시스템 같은 사내 패키지를 설치하려면 필요한 설정)
답:

2-3. 필요한 환경 변수 파일과, 그 값을 받는 방법
답:

2-4. 디자이너가 다루면 안 되는 비밀 값이나 파일
답:

## 3. 실행

3-1. 레포를 받은 직후 의존성을 설치하는 명령
답:

3-2. 개발 서버를 실행하는 명령과, 브라우저에서 여는 주소
답:

3-3. 로컬에서 화면을 보려면 로그인이나 테스트 계정, 테스트 데이터가 필요한지와 준비 방법
답:

3-4. 스토리북을 실행하는 명령과 주소. 이미 배포된 스토리북 주소가 있으면 그 주소
답:

## 4. 점검

4-1. 셋업이 끝났는지 확인하는 명령과, 정상일 때 보이는 결과
답:

4-2. PR 전에 로컬에서 돌려야 하는 검사(린트, 타입 검사, 테스트)의 명령
답:

4-3. 셋업 중에 자주 나는 오류와 해결 방법
답:

## 5. 작업 규칙

5-1. 브랜치 이름 규칙과 커밋 메시지 규칙
답:

5-2. PR 템플릿의 위치와, PR에 반드시 적어야 하는 항목
답:

5-3. 강제 푸시가 막혀 있는지 여부
답:

5-4. 디자이너가 수정해도 되는 폴더(화면과 스타일 코드)와 수정하면 안 되는 폴더
답:

5-5. 디자이너의 PR을 리뷰할 담당자 또는 담당 팀
답:
